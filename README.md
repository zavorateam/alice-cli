# Alice CLI

Неофициальный CLI-клиент и серверный интерфейс для Яндекс Алисы. Проект работает напрямую с внутренним WebSocket/RPC-протоколом Алисы и предоставляет три способа использования: интерактивный CLI, HTTP API и MCP через stdio.

Проект рассчитан на локальное использование. Учётные данные передаются непосредственно серверам Яндекса и не требуют отдельного облачного backend этого проекта.

## Возможности

- Интерактивный терминальный клиент в стиле Ollama.
- OAuth-токены `y0_...` и cookies как два варианта авторизации.
- Автоматическая проверка авторизации перед запуском.
- Работа с обычными и временными диалогами.
- Переключение между встроенными агентами и приложениями Алисы.
- Отображение потокового ответа, thinking-логов, виджетов и предложенных действий.
- HTTP API на FastAPI для вызова Алисы через `POST /chat`.
- MCP-сервер через stdio с динамическими инструментами для зарегистрированных агентов.
- Динамическая передача авторизации в MCP-вызовах.
- Автоматическое создание и сохранение device UUID.

## Требования

Python 3.8+ и зависимости из `requirements.txt`:

```text
websockets
asyncio
aioconsole
fastapi
uvicorn
aiohttp
```

Установка:

```bash
git clone https://github.com/zavorateam/alice-cli.git
cd alice-cli
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Для Windows активация виртуального окружения выполняется через `.venv\\Scripts\\activate` или соответствующий PowerShell-скрипт.

## Авторизация

Поддерживаются OAuth-токены и cookies.

OAuth-токен должен начинаться с `y0_`. Его можно передать напрямую:

```bash
python alice_cli.py --token y0_...
```

или через универсальный параметр:

```bash
python alice_cli.py --auth y0_...
```

Также можно указать путь к файлу токена:

```bash
python alice_cli.py --token ./token.txt
```

Файл токена должен содержать токен `y0_...` первой непустой строкой. При сохранении через встроенный механизм вторая строка может содержать `device_uuid=...`.

Cookies можно передать файлом:

```bash
python alice_cli.py --cookies .alice_cookies
```

Поддерживаются Netscape cookie-файлы и строки формата `name=value; name2=value2`. Для cookies проект использует необходимые значения для авторизации и пытается определить `device_uuid` из `alice_uuid` или `yandexuid`.

Также авторизация может быть задана переменными окружения:

```bash
export ALICE_TOKEN='y0_...'
```

```bash
export YANDEX_TOKEN='y0_...'
```

```bash
export ALICE_COOKIES='./cookies.txt'
```

Без явного параметра порядок поиска следующий: `ALICE_TOKEN`, `YANDEX_TOKEN`, `ALICE_COOKIES`, затем `token.txt`, `.alice_token`, `.alice_cookies` и `cookies.txt`.

Файл `.alice_device_uuid` используется для сохранения локального UUID устройства.

Перед началом работы CLI и HTTP-сервер выполняют healthcheck через RPC Алисы. HTTP 200 означает, что предоставленные учётные данные приняты; HTTP 401/403 трактуется как недействительный или отозванный токен/набор cookies.

## CLI

Запуск:

```bash
python alice_cli.py
```

Можно сразу выбрать агент и временный режим:

```bash
python alice_cli.py --agent pro --ephemeral
```

Полный набор параметров:

```text
--auth AUTH          Универсальный источник токена или cookies
--token TOKEN        OAuth-токен или путь к файлу токена
--cookies PATH       Путь к файлу cookies
--agent AGENT        Начальный агент, по умолчанию pro
-e, --ephemeral      Запустить временную сессию
-v, --verbose        Подробный лог WebSocket/RPC
```

### Команды CLI

Команды можно вводить как с `/`, так и без него.

```text
help, ?
list, agents
agent <имя>
model <имя>
new
dialogs
ephemeral on/off
clear
exit, bye, quit, q
```

`list` и `agents` показывают зарегистрированные приложения и агенты.

`agent <имя>` и `model <имя>` переключают активный режим. Начальный режим задаётся параметром `--agent`.

`new` создаёт новый диалог. Если включён `ephemeral`, созданный диалог помечается как временный.

`dialogs` показывает известные текущей сессии диалоги.

`ephemeral on` включает временный режим и сразу создаёт новый временный диалог. При завершении менеджер удаляет временные диалоги через RPC Алисы. `ephemeral off` отключает создание новых временных диалогов, но уже созданные временные диалоги остаются временными до завершения сессии.

После ответа Алиса может вернуть варианты действий, адреса или тарифы. Если они отображены с номерами, ввод соответствующего номера отправляет выбранный payload как `suggested_input`.

## HTTP API

HTTP-сервер запускается тем же `alice_server.py`:

```bash
python alice_server.py --http
```

По умолчанию сервер слушает `127.0.0.1:8000`. Host и порт можно изменить:

```bash
python alice_server.py --http --host 0.0.0.0 --port 8000
```

Параметры HTTP-сервера:

```text
--auth AUTH          Универсальный источник авторизации
--token TOKEN        OAuth-токен или путь к файлу токена
--cookies PATH       Путь к cookies
--http               Запустить HTTP API вместо MCP
--host HOST          HTTP host, по умолчанию 127.0.0.1
--port PORT          HTTP port, по умолчанию 8000
-v, --verbose        Подробный лог
```

### `POST /chat`

Это единственный прикладной HTTP endpoint проекта. API не является OpenAI-compatible API и не реализует `/v1/chat/completions`, `/dialogs` или другие старые маршруты из предыдущей версии README.

Тело запроса — обычный UTF-8 текст, а не JSON. Авторизацию можно передать в `Authorization` или `X-Alice-Auth`.

Для OAuth используйте само значение токена:

```bash
curl -X POST http://127.0.0.1:8000/chat \\
  -H 'Content-Type: text/plain; charset=utf-8' \\
  -H 'Authorization: y0_...' \\
  --data 'Привет, Алиса!'
```

В ответ сервер возвращает обычный `text/plain` с финальным текстом ответа Алисы.

Если сервер запущен без предварительно заданной авторизации, запрос должен содержать заголовок `Authorization` или `X-Alice-Auth` с источником авторизации, который понимает модуль авторизации. При корректных credentials сервер создаёт отдельный `AliceAgentManager` для этого запроса.

Коды ошибок прикладного endpoint:

```text
200   Успешный ответ Алисы
401   Отсутствуют или недействительны credentials
500   Алиса не вернула корректный финальный ответ
```

Поскольку используется FastAPI, при запуске HTTP-сервера также доступны автоматически генерируемые служебные маршруты документации FastAPI, включая `/docs` и `/openapi.json`.

## MCP

В режиме без `--http` `alice_server.py` работает как MCP-сервер через stdio. JSON-RPC сообщения передаются построчно через stdin/stdout. Интерактивный `input()` в MCP-режиме не используется.

Запуск:

```bash
python alice_server.py
```

Для MCP можно заранее задать credentials:

```bash
python alice_server.py --token y0_...
```

Также MCP допускает полностью динамическую авторизацию через параметр `auth` инструментов. Это позволяет запустить сервер без заранее заданного токена и передавать источник авторизации непосредственно при вызове инструмента.

MCP server объявляет стандартные операции `initialize`, `notifications/initialized`, `tools/list`, `tools/call` и `ping`.

### Инструменты

Для каждого зарегистрированного агента создаётся инструмент:

```text
alice_ask_<agent_id>
```

Параметры:

```text
message    string, обязательный
 dialog_id string, необязательный
auth       string, необязательный
```

`auth` принимает OAuth-токен `y0_...` либо путь к файлу токена/cookies.

Также существует:

```text
alice_click_action
```

Параметры:

```text
action_text string, обязательный
dialog_id   string, необязательный
auth        string, необязательный
```

`alice_click_action` отправляет выбранный вариант как `suggested_input`.

Результат `alice_ask_<agent_id>` содержит JSON с `dialog_id`, `text`, `thinking_steps`, `widgets` и `suggested_actions` внутри MCP text content.

## Протокол и внутренняя архитектура

Проект не использует официальный публичный API Алисы. Основной транспорт диалога — WebSocket:

```text
wss://uniproxy.alice.yandex.ru/uni.ws
```

RPC-вызовы выполняются через:

```text
https://rpc.alice.yandex.ru
```

В процессе инициализации WebSocket клиент отправляет `System.SynchronizeState`, после чего поддерживает состояние подписок диалогов и обрабатывает streaming-ответы `DeferredAliceResponse`.

Для RPC используются, в частности, запросы получения Alice Apps, списка диалогов и удаления диалогов. Эти внутренние RPC endpoints не являются публичным HTTP API этого проекта и могут измениться на стороне Яндекса.

Основные компоненты:

- `alice_auth.py` — credentials, cookies/token parsing, device UUID и healthcheck.
- `alice_server.py` — WebSocket/RPC клиент, менеджер агентов, MCP и FastAPI HTTP API.
- `alice_cli.py` — интерактивный терминальный интерфейс.
- `agents/` — встроенные агенты и registry.
- `requirements.txt` — Python-зависимости.

## Безопасность

Не добавляйте `token.txt`, `.alice_token`, `.alice_cookies`, `cookies.txt` или другие файлы с действующими credentials в Git.

OAuth-токены и cookies дают доступ к учётной записи и должны рассматриваться как секреты. При использовании HTTP API на `0.0.0.0` сервер не предоставляет отдельный механизм авторизации поверх переданных Alice credentials, поэтому не следует без дополнительной защиты выставлять его непосредственно в публичную сеть.

Проект взаимодействует с внутренними интерфейсами Яндекса, поэтому изменения протокола, авторизации или серверной логики Алисы могут нарушить работу клиента без изменений в самом репозитории.

## Ограничения

Проект зависит от текущего поведения внутренних WebSocket/RPC интерфейсов Алисы.

HTTP API намеренно минимален и предоставляет только текстовый `POST /chat`; OpenAI Chat Completions API здесь не реализован.

Список Alice Apps является динамическим и зависит от ответа RPC `get_alice_apps` и текущей авторизации.

## Лицензия и использование

Перед использованием проекта проверьте применимые условия использования сервисов Яндекса. Репозиторий не является официальным клиентом Яндекса и не утверждает наличие официальной поддержки со стороны Яндекса.
